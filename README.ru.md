# Display Model Optimizer

**Клиентская оптимизация отрисовки моделей display-сущностей в Minecraft.**

[English](README.md) · [Скачать](https://github.com/Nodelll/display-model-optimizer/releases) · [Сообщить об ошибке](https://github.com/Nodelll/display-model-optimizer/issues) · [Сборки](https://github.com/Nodelll/display-model-optimizer/actions)

Display Model Optimizer сокращает повторную работу при отрисовке `item_display` и `block_display`. Мод подходит для декораций, кастомной мебели, витрин и других мест с большим количеством моделей в одиночных мирах и на серверах.

## Возможности

- **Кэш моделей блоков:** одинаковые поддерживаемые модели готовятся один раз за кадр.
- **Межкадровый кэш геометрии (0.8.0 alpha):** преобразованная геометрия видимых block_display повторно используется через необязательный Fabric Renderer API.
- **Ускоренный поиск групп:** снижаются затраты на группировку моделей для отрисовки.
- **Настраиваемая дальность:** дополнительный лимит отрисовки **18 блоков по умолчанию**.
- **Отсечение вне кадра:** реальные границы моделей позволяют Minecraft скрывать item_display и block_display вне поля зрения камеры; Entity Culling для этого не требуется.
- **Интеграция с Entity Culling:** границы моделей позволяют скрывать display-сущности, полностью закрытые непрозрачными блоками.

## Требования

| Компонент | Версия / назначение |
| --- | --- |
| Minecraft | **26.3** |
| Fabric Loader | **0.19.5 или новее** |
| Java | **25** |
| Entity Culling | Необязателен; нужен для скрытия за блоками. Проверена версия **1.11.3** для Minecraft 26.3. |
| Mod Menu | Необязателен; нужен для экрана настроек. Проверена версия **21.0.0**. |

Мод устанавливается на **клиент**. Кэширование моделей, ускоренный поиск групп и ограничение дальности работают без Entity Culling. Fabric API необязателен; новый межкадровый кэш геометрии требует **Fabric Renderer API 17.0.16+**. Остальные функции доступны без него.

## Установка и настройки

1. Скачать JAR из раздела [Releases](https://github.com/Nodelll/display-model-optimizer/releases).
2. Удалить предыдущую версию из папки `mods`, поместить туда новый JAR и перезапустить Minecraft.
3. Открыть **Mod Menu → Display Model Optimizer** либо вручную изменить `config/display-model-optimizer.properties` и перезапустить игру.

**Максимальная дальность моделей по умолчанию — 18 блоков.** Параметр `displayRenderDistance` можно увеличить для дальних моделей или установить в **0**, чтобы сохранить исходную дальность игры и сервера. Лимит применяется к `item_display` и `block_display`.

Отсечение вне кадра выполняется обычной проверкой камеры Minecraft и работает без Entity Culling. Новый параметр `cullOffscreenDisplays` по умолчанию включён и настраивается отдельно от `cullOccludedDisplays`. Учитываются реальные размеры, преобразования и интерполяция модели; видимая часть крупной модели сохраняет её отрисовку. Подробнее — в [документации отсечения](docs/CULLING.md).

Для скрытия за блоками используется установленный Entity Culling и его правила прозрачности. Полные непрозрачные блоки закрывают модели; стекло и невидимые барьеры не считаются непрозрачной стеной. Анимированные модели предметов, перемещающиеся display-сущности и модели с неизвестными границами могут оставаться видимыми.

При первом запуске с новым конфигом настройки переносятся из единственного файла `.properties` в папке `config`, содержащего полный набор семи базовых параметров прежних версий. Исходный файл сохраняется, а существующий новый конфиг имеет приоритет. Недостающие параметры добавляются автоматически: `cullOffscreenDisplays=true` и новый `cacheBlockDisplayGeometry=true`; прежние значения сохраняются. При неоднозначности или неполном наборе параметров нужный файл можно заранее переименовать вручную.

## Результаты тестирования FPS

В экспериментальной **0.8.0 alpha** появился параметр `cacheBlockDisplayGeometry`: **Mod Menu → Display Model Optimizer → Дополнительно → Кэш геометрии block_display**. Он сохраняет преобразованную геометрию между кадрами, чтобы ускорить подготовку видимых моделей, включая сцену перед камерой и за стеклом. Освещение, оттенки и преобразования сущности рассчитываются обычным способом; кэш ограничен по объёму и сбрасывается при смене ресурсов, мира и настроек. Подробнее — [алгоритм и порядок сравнения](docs/BLOCK_GEOMETRY_CACHE.md). **Замеры FPS ниже относятся к 0.7.1 без этой функции.**

Замеры предоставлены **15 октября 2026 года**: **DMO 0.7.1**, отдельный инструмент DMO Benchmark, план `quick`, одиночный мир с тестовой ареной на **600 item/block display-сущностей**.

### Условия и методика

- **Компьютер:** AMD Ryzen 5 5600, NVIDIA GeForce RTX 3070 8 ГБ, 16 ГБ оперативной памяти.
- **Зафиксированная сборка:** Minecraft 26.3, Fabric Loader 0.19.5, Java 25, Sodium 0.9.2, Iris 1.11.7 и Entity Culling 1.11.3.
- **Параметры из отчёта без шейдеров:** окно 1920 × 1009, дальность прорисовки 16 чанков, симуляции — 12 чанков, FOV 85, максимальный heap Java — 4 ГиБ.
- **Прогон с шейдерами:** Complementary Unbound r5.9.3; включение подтверждено параметром Iris `enableShaders=true`.

Каждый прогон содержит **16 измеряемых этапов по 20 секунд**. Для каждой из четырёх сцен использовался порядок **выключен → включён → включён → выключен**: по два замера каждого режима после разогрева и стабилизации. FPS в таблицах рассчитан как **суммарное количество кадров ÷ суммарное время измерения** двух повторов. Значения округлены.

В режиме **OFF** DMO выключен настройкой, остальные установленные моды продолжают работать. В режиме **FULL** DMO включён, а дополнительный лимит дальности дисплеев в этих сравнениях установлен в **0**. Поэтому таблицы показывают дополнительный эффект DMO в этой сборке без сокращения дальности моделей. Базовый режим также содержит Sodium, Iris и Entity Culling.

### Без шейдеров

| Сцена | DMO выключен, FPS | DMO включён, FPS | Изменение |
| --- | ---: | ---: | ---: |
| Дисплеи перед камерой | 312,3 | 312,3 | ≈0% |
| Камера развёрнута от дисплеев | 1037,3 | 1228,0 | +18,4% |
| Между камерой и дисплеями — непрозрачная стена | 309,4 | 567,6 | **+83,5%** |
| Между камерой и дисплеями — стекло | 308,2 | 307,4 | −0,3% |

### С Complementary Unbound r5.9.3

| Сцена | DMO выключен, FPS | DMO включён, FPS | Изменение |
| --- | ---: | ---: | ---: |
| Дисплеи перед камерой | 184,5 | 184,2 | −0,2% |
| Камера развёрнута от дисплеев | 380,8 | 382,9 | +0,6% |
| Между камерой и дисплеями — непрозрачная стена | 185,1 | 325,2 | **+75,7%** |
| Между камерой и дисплеями — стекло | 181,7 | 181,3 | −0,2% |

### Время кадра и медленные кадры за непрозрачной стеной

| Рендер | Среднее время кадра, выкл. → вкл. | 1% low FPS, выкл. → вкл. |
| --- | ---: | ---: |
| Без шейдеров | 3,23 → 1,76 мс | 135,8–137,9 → 199,3–200,0 |
| Complementary Unbound r5.9.3 | 5,40 → 3,08 мс | 104,2–106,5 → 168,8–170,9 |

Для 1% low указан **диапазон двух отдельных повторов**. Это не объединённый процентиль всего прогона: в каждом этапе 1% low FPS рассчитывается по среднему времени 1% самых медленных кадров. Более высокое значение означает лучшую производительность на медленных кадрах. Среднее время кадра в этой сцене уменьшилось на **45,5% без шейдеров** и **43,1% с шейдерами**.

### Что изменилось

Среднее количество подготовленных состояний рендера дисплеев на кадр совпадало в обоих вариантах рендера:

| Сцена | DMO выключен | DMO включён |
| --- | ---: | ---: |
| Дисплеи перед камерой | 600 | 600 |
| Камера развёрнута от дисплеев | 60 | 30 |
| Между камерой и дисплеями — непрозрачная стена | 600 | 300 |
| Между камерой и дисплеями — стекло | 600 | 600 |

Это **подготовленные состояния рендера**; их количество отличается от числа вызовов отрисовки GPU и общего количества загруженных сущностей.

Самый большой измеренный эффект получен за непрозрачной стеной: **309,4 → 567,6 FPS без шейдеров** и **185,1 → 325,2 FPS с шейдерами**. Прирост наблюдался в обоих повторах и сопровождался улучшением 1% low.

При развороте камеры от дисплеев прирост составил **+18,4% без шейдеров**, а с шейдерами — только **+0,6%**, хотя количество подготовленных состояний также уменьшилось. Снижение этого счётчика само по себе не гарантирует пропорционального роста FPS. Перед камерой и за стеклом средний FPS почти не изменился.

Это предварительные результаты для **одного компьютера, одной синтетической арены и двух повторов каждого режима**. План quick включает несколько оптимизаций DMO совместно и не определяет вклад каждого алгоритма по отдельности. Результат зависит от сцены, оборудования, ресурс-паков и шейдеров; универсальный прирост FPS не заявляется.

## Сборка из исходников

Установить JDK 25 и Python 3, затем выполнить:

```sh
python3 build.py
```

Скрипт загружает зависимости с проверкой контрольных сумм, компилирует мод, запускает автоматические проверки и сохраняет JAR в `build/libs/`. Minecraft и сторонние библиотеки в готовый мод не включаются.

Путь к конкретному исполняемому файлу Java можно указать через `DISPLAY_MODEL_OPTIMIZER_JAVA`. При установленном Gradle и Java 25 также доступна команда `gradle build`.

## Состояние и проверки

Это **экспериментальная бета-версия**. Автоматические проверки охватывают поиск групп, независимость и время жизни кэшей, перенос настроек, расчёт границ моделей и сцены на настоящем движке Entity Culling. Переименованные mixin-компоненты также применены к официальным классам Minecraft 26.3 совместно с оригинальными mixin-компонентами Entity Culling.

Эти проверки не заменяют запуск Minecraft и замер FPS в реальной сцене. Работу полной сборки и шейдеров нужно проверять в игре. Доступны [заметки о проверках](docs/TESTING.md), [результаты](VALIDATION.json) и [техническая документация](docs/DEVELOPMENT.ru.md).
