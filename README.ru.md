# Display Model Optimizer

**Клиентская оптимизация отрисовки моделей display-сущностей в Minecraft.**

[English](README.md) · [Скачать](https://github.com/Nodelll/display-model-optimizer/releases) · [Сообщить об ошибке](https://github.com/Nodelll/display-model-optimizer/issues) · [Сборки](https://github.com/Nodelll/display-model-optimizer/actions)

Display Model Optimizer сокращает повторную работу при отрисовке `item_display` и `block_display`. Мод подходит для декораций, кастомной мебели, витрин и других мест с большим количеством моделей в одиночных мирах и на серверах.

**Пре-релизные порты:** для Minecraft **26.2** и **1.21.11** доступны отдельные сборки **0.8.0-beta.1**. [Зависимости, отличия версий и сборка](ports/README.md). Стабильная сборка и FPS-замеры ниже относятся к **26.3**.

## Возможности

- **Кэш моделей блоков:** одинаковые поддерживаемые модели готовятся один раз за кадр.
- **Межкадровый кэш геометрии (0.8.0):** преобразованная геометрия видимых block_display повторно используется через необязательный Fabric Renderer API.
- **Ускоренный поиск групп:** снижаются затраты на группировку моделей для отрисовки.
- **Настраиваемая дальность:** дополнительный лимит отрисовки **18 блоков по умолчанию**.
- **Отсечение вне кадра:** реальные границы моделей позволяют Minecraft скрывать item_display и block_display вне поля зрения камеры; Entity Culling для этого не требуется.
- **Интеграция с Entity Culling:** границы моделей позволяют скрывать display-сущности, полностью закрытые непрозрачными блоками.

## Требования

| Компонент | Версия / назначение |
| --- | --- |
| Minecraft | **26.3** |
| Fabric Loader | **0.19.5 или новее** |
| Java | **25** |
| Entity Culling | Необязателен; нужен для скрытия за блоками. Проверена версия **1.11.3** для Minecraft 26.3. |
| Mod Menu | Необязателен; нужен для экрана настроек. Проверена версия **21.0.0**. |

Мод устанавливается на **клиент**. Кэширование моделей, ускоренный поиск групп и ограничение дальности работают без Entity Culling. Fabric API необязателен; новый межкадровый кэш геометрии требует **Fabric Renderer API 17.0.16+**. Остальные функции доступны без него.

## Установка и настройки

1. Скачать JAR из раздела [Releases](https://github.com/Nodelll/display-model-optimizer/releases).
2. Удалить предыдущую версию из папки `mods`, поместить туда новый JAR и перезапустить Minecraft.
3. Открыть **Mod Menu → Display Model Optimizer** либо вручную изменить `config/display-model-optimizer.properties` и перезапустить игру.

Если для тестов alpha был установлен DMO Benchmark 1.1.0, после тестирования удалить JAR тестера: он требует точную alpha-сборку и является отдельным инструментом, а не частью стабильного мода.

**Максимальная дальность моделей по умолчанию — 18 блоков.** Параметр `displayRenderDistance` можно увеличить для дальних моделей или установить в **0**, чтобы сохранить исходную дальность игры и сервера. Лимит применяется к `item_display` и `block_display`.

Отсечение вне кадра выполняется обычной проверкой камеры Minecraft и работает без Entity Culling. Новый параметр `cullOffscreenDisplays` по умолчанию включён и настраивается отдельно от `cullOccludedDisplays`. Учитываются реальные размеры, преобразования и интерполяция модели; видимая часть крупной модели сохраняет её отрисовку. Подробнее — в [документации отсечения](docs/CULLING.md).

Для скрытия за блоками используется установленный Entity Culling и его правила прозрачности. Полные непрозрачные блоки закрывают модели; стекло и невидимые барьеры не считаются непрозрачной стеной. Анимированные модели предметов, перемещающиеся display-сущности и модели с неизвестными границами могут оставаться видимыми.

При первом запуске с новым конфигом настройки переносятся из единственного файла `.properties` в папке `config`, содержащего полный набор семи базовых параметров прежних версий. Исходный файл сохраняется, а существующий новый конфиг имеет приоритет. Недостающие параметры добавляются автоматически: `cullOffscreenDisplays=true` и новый `cacheBlockDisplayGeometry=true`; прежние значения сохраняются. При неоднозначности или неполном наборе параметров нужный файл можно заранее переименовать вручную.

## Результаты тестирования FPS

**15 октября 2026 года** выполнены два полных прогона по **48 этапов**: **DMO 0.8.0-alpha.1**, **DMO Benchmark 1.1.0**, без шейдеров и с **Complementary Unbound r5.9.3, пресет High**. Пресет High указан тестировщиком; настройки Iris подтверждают шейдер-пак и включение шейдеров. Релиз **0.8.0** выпускает измеренную реализацию; при проверке релиза сравниваются байты рабочих классов с протестированной сборкой.

### Условия и методика

- **Компьютер:** AMD Ryzen 5 5600, NVIDIA GeForce RTX 3070 8 ГБ, 16 ГБ оперативной памяти.
- **Клиент:** Minecraft 26.3, Fabric Loader 0.19.5, Microsoft Java 25.0.1, Fabric API 0.163.0+26.3, Sodium 0.9.2, Iris 1.11.7 и Entity Culling 1.11.3.
- **Стенд:** 600 сущностей — **300 item_display и 300 block_display**; без стороннего ресурс-пака; **1920 × 1080**, прорисовка 16 чанков, симуляция 12 чанков, FOV 90, максимальный heap Java 4 ГиБ.
- **Каждый прогон:** первый прогрев 60 секунд, стабилизация последующих этапов по 8 секунд; по два замера каждого режима длительностью **30 секунд**, порядок **A → B → B → A**. Отдельные диагностические окна по 2 секунды исключены из FPS. Каждый прогон занял около 33 минут; все этапы завершены, исходные настройки восстановлены.
- **Расчёт:** суммарное число кадров делится на суммарное время двух повторов. Проценты рассчитаны по неокруглённым значениям; таблицы округлены.

**OFF** выключает DMO настройкой; Sodium, Iris и Entity Culling остаются установленными. **FULL** включает функции DMO, дополнительная дальность установлена в **0**. Это сравнение в одной сборке с сохранением исходной дальности моделей. В отдельных тестах меняется ровно один параметр; проверка дальности вынесена отдельно.

### Отдельные оптимизации

Главный переключатель остаётся включённым, меняется одна функция, остальные оптимизации выключены. Для кэша геометрии используются одно повторяющееся состояние блока, шесть разных состояний либо состояния, меняющиеся каждую секунду. В стенде также остаются 300 item_display.

| Функция | Без шейдеров, FPS | Изменение | Unbound High, FPS | Изменение |
| --- | ---: | ---: | ---: | ---: |
| Индекс групп отрисовки | 287,3 → 294,2 | +2,4% | 116,9 → 118,2 | +1,1% |
| Кэш модели на кадр* | 267,0 → 265,9 | −0,4% | 105,1 → 107,0 | +1,8% |
| Кэш геометрии: одинаковые блоки | 262,8 → 278,7 | +6,1% | 107,1 → 109,9 | +2,7% |
| Кэш геометрии: разные блоки | 285,2 → 298,8 | +4,7% | 116,1 → 120,2 | +3,5% |
| Кэш геометрии: меняющиеся блоки | 283,1 → 296,1 | +4,6% | 115,7 → 119,3 | +3,1% |
| Отсечение вне камеры | 1018,0 → 1227,1 | +20,5% | 185,6 → 332,7 | +79,3% |
| Отсечение за непрозрачной стеной | 283,3 → 573,5 | +102,4% | 114,7 → 152,1 | +32,7% |
| Лимит дальности: 0 → 18 блоков** | 283,7 → 1417,4 | +399,6% | 114,4 → 368,3 | +222,0% |

\* **Кэш на кадр: BYPASS в этой сборке.** Дополнительные данные рендерера сохраняют исходный путь подготовки. Попаданий в снимки моделей нет, поэтому небольшой разброс FPS нельзя приписывать работающему кэшу.

\*\* В тесте дальности все 600 дисплеев находятся дальше 18 блоков. При включении лимита они полностью исключаются из подготовки; прирост относится к этому сокращению видимости.

### Время кадра за непрозрачной стеной

| Рендер | Среднее время кадра OFF → FULL | 1% low FPS OFF → FULL |
| --- | ---: | ---: |
| Без шейдеров | 3,41 → 1,56 мс | 137,8–141,7 → 231,7–234,7 |
| Complementary Unbound r5.9.3 — High | 8,54 → 6,05 мс | 66,3–66,4 → 87,4–87,8 |

Для 1% low приведён **диапазон двух отдельных повторов**, а не объединённый процентиль. В каждом этапе используется величина, обратная среднему времени 1% самых медленных кадров.

### Диагностика и ограничения

- Новый кэш зарегистрировал **1 046 400 повторов геометрии без шейдеров** и **846 600 с Unbound High** в отдельных диагностических окнах. В прогретых сценах наблюдались попадания. Изменения блоков на клиенте и сброс при перезагрузке ресурсов проверены; все десять автоматических проверок пройдены в обоих прогонах.
- За непрозрачной стеной количество подготовленных состояний item_display уменьшилось **300 → 0**, а block_display осталось **300 → 300**. Позади камеры: **30 предметов + 30 блоков → 0 предметов + 30 блоков**. На проверенном пути FRAPI/Sodium DMO не получил пригодные границы моделей блоков: отсечение block_display вне камеры и за стеной здесь остаётся ограничением. Кэширование и лимит дальности применяются и к блокам. Это счётчики подготовки состояний, а не вызовов GPU.
- В меняющейся сцене с шейдерами средний по этапам 1% low снизился **64,9 → 60,0 FPS (−7,6%)**, хотя средний FPS вырос. Длинные кадры совпадают с паузами GC около **11–15 мс**; нужны дополнительные повторы для проверки воспроизводимости.
- Первый измеренный кадр без шейдеров занял **75 мс** и ухудшил 1% low этого этапа. Положение солнца между снимками меняется: время суток и погода не фиксировались. Небольшие процентные различия ориентировочны; ABBA уменьшает влияние дрейфа, но не устраняет его.
- Устойчивого роста private memory Java за эти два прогона по 33 минуты не наблюдалось. С шейдерами private memory составляла около **3,9–4,2 ГиБ**, VRAM **3,0–3,2 ГиБ**, максимальная температура GPU — **75 °C**. Показания GPU относятся ко всему адаптеру.

Результаты относятся к **одному компьютеру, одной синтетической арене и двум повторам каждого режима**. Они не доказывают универсальный прирост FPS, правильность каждого пикселя или совместимость со всеми ресурс-паками и шейдерами. Анимированные модели, движущиеся дисплеи и неизвестные границы могут оставаться видимыми. Нужен дополнительный визуальный осмотр моделей конкретного сервера.

## Сборка из исходников

Установить JDK 25 и Python 3, затем выполнить:

```sh
python3 build.py
```

Скрипт загружает зависимости с проверкой контрольных сумм, компилирует мод, запускает автоматические проверки и сохраняет JAR в `build/libs/`. Minecraft и сторонние библиотеки в готовый мод не включаются.

Путь к конкретному исполняемому файлу Java можно указать через `DISPLAY_MODEL_OPTIMIZER_JAVA`. При установленном Gradle и Java 25 также доступна команда `gradle build`.

## Состояние и проверки

**0.8.0 — стабильный релиз для Minecraft 26.3.** Автоматические проверки охватывают поиск групп, независимость и время жизни кэшей, перенос настроек, расчёт границ моделей и сцены на настоящем движке Entity Culling. Переименованные mixin-компоненты также применены к официальным классам Minecraft 26.3 совместно с оригинальными mixin-компонентами Entity Culling.

Выше приведены два полных игровых прогона без шейдеров и с Complementary Unbound r5.9.3 High. Автоматические проверки и эти замеры не доказывают совместимость с любой сборкой, моделью или шейдер-паком. Доступны [заметки о проверках](docs/TESTING.md), [результаты](VALIDATION.json) и [техническая документация](docs/DEVELOPMENT.ru.md).
