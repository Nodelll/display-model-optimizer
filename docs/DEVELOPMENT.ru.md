# Display Model Optimizer — Minecraft 26.3

Автор: **Nodelll**. Клиентский мод для Fabric Loader 0.19.5 и новее, Java 25.

Версия **0.5.1** использует название **Display Model Optimizer** во всех идентификаторах, Java-пакетах, ресурсах, настройках и сборочных файлах. Мод оптимизирует отрисовку сущностей `item_display` и `block_display` в одиночных мирах и на серверах. Дальность по умолчанию — **18 блоков**; доступны кэш моделей блоков, ускоренный поиск групп отрисовки и скрытие за непрозрачными блоками через Entity Culling.

## Установка

1. Удалить предыдущий JAR Display Model Optimizer из `mods` и поместить туда `display-model-optimizer-0.5.1+mc26.3.jar`.
2. Перезапустить Minecraft.
3. Проверить наличие Display Model Optimizer 0.5.1 в Mod Menu или строки `[Display Model Optimizer] 0.5.1+mc26.3` в `logs/latest.log`.

Установка выполняется на клиенте. Используются Fabric Loader и fastutil, который уже входит в Minecraft.

Перед обновлением удалить предыдущий JAR из `mods`. При первом запуске с новым именем конфига мод ищет в папке `config` единственный файл `.properties` с полным набором его семи параметров и переносит значения вместе с неизвестными свойствами в `config/display-model-optimizer.properties`. Исходный файл сохраняется. Существующий новый конфиг имеет приоритет. Если подходящих файлов несколько или набор параметров неполный, автоматический выбор не выполняется: нужный конфиг можно заранее переименовать вручную.

## Скрытие за непрозрачными блоками

Для этой функции требуется отдельно установленный **Entity Culling**. Проверено взаимодействие с Fabric-версией **1.11.3 для Minecraft 26.3**. Display Model Optimizer не включает копию этого мода и не создаёт дополнительный поток проверки видимости. Без Entity Culling остальные оптимизации продолжают работать, а экран сообщает, что для скрытия за стенами нужен этот мод.

В Mod Menu включить **«Скрывать модели за блоками»**; настройка включена по умолчанию. Проверка прозрачности выполняется по правилам Entity Culling: полные непрозрачные блоки закрывают модели, стекло, тонированное стекло и невидимые barrier-блоки их не закрывают. Поведение частичных блоков и листвы зависит от правил и настроек Entity Culling. Прозрачная текстура ресурспака на обычном непрозрачном блоке не меняет его свойства для проверки видимости.

Границы извлекаются из вершин модели блока или extents модели предмета, затем учитываются смещение, масштаб, поворот и отдельный поворот item_display. Для интерполяции и billboard-моделей используются расширенные границы, охватывающие весь поворот. При перемещении самой сущности, анимации динамической item-модели или неизвестных границах выбирается сохранение видимости. При обновлении модели, позы, настроек и перезагрузке ресурсов устаревшие результаты сбрасываются.

Проверка видимости асинхронная: после появления или изменения модель временно остаётся видимой, пока Entity Culling обновляет результат. Ограничение дальности — отдельная настройка, по умолчанию 18 блоков; можно установить `displayRenderDistance=0` и использовать только скрытие за стенами. Сущности interaction, серверные координаты, хитбоксы и клиентские width/height display-сущностей не меняются.

## Настройки через Mod Menu

Для Minecraft 26.3 поддерживается Mod Menu **21.0.0**. Открыть список модов → **Display Model Optimizer** → кнопку настроек. Дополнительная библиотека экрана конфигурации не требуется. Mod Menu — необязательная зависимость: без него мод использует файл настроек.

Иконка: куб с молнией; PNG находится в `assets/display_model_optimizer/icon.png` внутри JAR. Описание и краткая строка используют стандартные ключи Mod Menu `modmenu.descriptionTranslation.display_model_optimizer` и `modmenu.summaryTranslation.display_model_optimizer`. На русском языке игры показывается русский вариант, на английском — английский; для остальных языков применяется стандартный английский резервный перевод Minecraft. Если пользователь отключил перевод описаний в Mod Menu, показывается русское описание из `fabric.mod.json`.

- Русский: «Оптимизирует отрисовку сущностей item_display и block_display с помощью кэширования моделей блоков, ограничения дальности и скрытия за блоками через Entity Culling.»
- English: “Optimizes item_display and block_display rendering with block model caching, a distance limit, and occlusion culling through Entity Culling.”

Экран доступен на русском и английском языках. Можно менять все семь настроек ниже. **Сохранить** записывает настройки и применяет их; **Отмена** и Escape возвращают к списку модов без сохранения. **Сбросить** возвращает черновик к исходным значениям, которые применятся только после сохранения. Неправильные числа выделяются красным и блокируют сохранение; допустимые диапазоны описаны в подсказках.

Дальность и переключатели начинают использоваться при следующих обращениях рендера. Лимит кэша применяется со следующего кадра; параметры индекса вызывают создание нового индекса в существующей группе. Защитное отключение после ошибки проверки индекса по-прежнему действует до перезапуска, и экран сообщает об этом, если оно произошло.

## Настройки

При первом запуске создаётся `config/display-model-optimizer.properties`:

```properties
enabled=true
minimumListSize=32
verifyEvery=256
cacheBlockDisplayModels=true
modelCacheLimit=1024
displayRenderDistance=18
cullOccludedDisplays=true
```

- `enabled` — включение оптимизации.
- `minimumListSize` — минимальное количество состояний для создания индекса. Малые списки используют обычный поиск.
- `verifyEvery` — раз в сколько обращений сверять ответ с обычным поиском. Значение 256 оставляет выборочную проверку включённой; 0 отключает её.
- `cacheBlockDisplayModels` — кэшировать повторную подготовку одинаковых блоков в block_display в пределах кадра.
- `modelCacheLimit` — максимум комбинаций модели, блока, контекста и seed в кэше. Кэш освобождается в конце прохода извлечения и очищается в начале следующего, включая случай прерывания предыдущего прохода. 0 отключает хранение.
- `cullOccludedDisplays` — добавлять границы моделей display-сущностей для скрытия за непрозрачными блоками через установленный Entity Culling. По умолчанию включено.
- `displayRenderDistance` — дополнительная максимальная дальность отрисовки `item_display` и `block_display` в блоках. По умолчанию 18. Значение 0 сохраняет исходную дальность. Ограничение также затрагивает другие серверные декорации из этих сущностей; текстовые display-сущности используют исходный путь.

Изменения через экран применяются после нажатия «Сохранить» без перезапуска Minecraft. При ручном редактировании файла нужен перезапуск. При несовпадении результатов проверки индекса оптимизация автоматически отключается до следующего запуска, а предупреждение записывается в журнал.

При обновлении отсутствующие настройки дописываются автоматически с указанными значениями, а существующие значения сохраняются. Если конфиг уже создан, для дальности 18 нужно указать её в Mod Menu и сохранить либо вручную заменить `displayRenderDistance` в `config/display-model-optimizer.properties`.

Лимит уменьшает количество подготавливаемых и отрисовываемых display-сущностей за указанной дистанцией. Дальние модели появляются по мере приближения. При необходимости можно увеличить значение до 32/48/64 или установить 0. Обычные блоки мира и сущности interaction используют исходные правила клиента.

## Проверка результата в игре

В том же месте и с теми же настройками сравнить FPS и плавность кадра до и после установки. Для записи профиля клиента:

```text
/sparkc profiler start --timeout 60 --thread *
```

Найденная дорогая ветка проходит через `RenderTypeFeatureRenderer$Group.getOrAddDraw` и `List.indexOf`. После установки вместо основной части перебора должен использоваться `DrawLookupIndex.findFirst`. Проценты в профиле зависят от остальных работ клиента и не являются прямым измерением прироста FPS.


## Сборка из исходников

С установленными Python 3 и JDK 25:

```text
python build.py
```

Скрипт скачивает зависимости, Mod Menu 21.0.0, Entity Culling 1.11.3 и официальный клиент Minecraft для компиляции, проверяет SHA-256, компилирует классы и запускает проверки поиска, срока жизни и независимости кэшированных данных, границ дистанции, миграции и сохранения настроек. Готовый JAR находится в `build/libs`. Код Minecraft, Mod Menu, Entity Culling и остальные зависимости в мод не включаются. Можно указать путь к Java через переменную `DISPLAY_MODEL_OPTIMIZER_JAVA`.

Альтернативный вариант при установленном Gradle:

```text
gradle build
```

## Устройство

Ускоренный поиск заменяет единственный вызов `List.indexOf` внутри `getOrAddDraw`. Условия объединения геометрии, выбор состояния, создание draw и обход готовых draw выполняет исходный код Minecraft. Индекс сохраняет первое равное состояние, включая дубликаты, принадлежит конкретному объекту Group и освобождается вместе с ним.

Кэш моделей подменяет только вызов `BlockModel.update` внутри `BlockModelResolver.update`. Исходная очистка состояния, вычисление света и TAIL-хук Iris, задающий состояние блока для шейдеров, остаются на прежнем пути. Кэш применяется исключительно к контексту block_display во время `GameRenderer.extract`. Модели со special renderer используют исходную подготовку. Кэш копирует списки, оттенки и матрицы, поэтому последующая модификация одного render state не меняет сохранённые контейнеры. При неизвестных дополнительных полях состояния модели кэш автоматически пропускается для совместимости.

Проверка `validation/MixinSmokeTest.java` применила все девять mixin-компонентов к восьми классам официального клиента 26.3. Проверены хуки, сохранность исходных операций и стеки методов. Изменённый `BlockModelRenderState` также создан в изолированном загрузчике: вызовы accessors и копирование данных выполняются, свет отдельного состояния сохраняется. Стенд использует LaunchWrapper с предупреждениями совместимости; полная сборка Minecraft с пользовательскими модами не запускалась. `validation/ModMenuSmokeTest.java` создаёт фабрику экрана через API настоящего Mod Menu 21.0.0; полноценный GUI в запущенной игре не проверялся.

В исходниках нет встроенного кода Minecraft или сторонних библиотек. Mixin и fastutil предоставляются средой игры.

Проверки `BoundsTest` выполняют выборку точек трансформированной модели и сравнивают их с рассчитанными границами, включая отрицательный масштаб, двойной поворот и интерполяцию. На настоящем движке OcclusionCulling из Entity Culling проверены непрозрачная стена, прозрачные ячейки, окно, край стены и подход с другой стороны. Дополнительно применены оригинальные EntityRendererMixin и WorldRendererMixin из JAR Entity Culling 1.11.3 совместно с изменениями Display Model Optimizer. Полная клиентская сборка с шейдерами на сервере не запускалась.
