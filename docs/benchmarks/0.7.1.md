# Historical DMO 0.7.1 benchmarks

These earlier runs used a different window size, FOV and measurement duration. Use the current README for the 0.8.0 implementation.


The **0.8.0 alpha** branch adds an independent `cacheBlockDisplayGeometry` switch under **Advanced**. It stores converted block-display geometry across frames, with capacity and quad budgets and automatic invalidation. See [algorithm, CPU checks and in-game comparison](docs/BLOCK_GEOMETRY_CACHE.md). The in-game FPS measurements below are for **0.7.1**, before this feature.

User-submitted measurements from **15 October 2026**, using **DMO 0.7.1** and the separate DMO Benchmark companion's `quick` plan in a singleplayer arena with **600 item/block display entities**.

### Test setup and method

- **Hardware:** AMD Ryzen 5 5600, NVIDIA GeForce RTX 3070 8 GB, 16 GB RAM.
- **Reported client:** Minecraft 26.3, Fabric Loader 0.19.5, Java 25, Sodium 0.9.2, Iris 1.11.7 and Entity Culling 1.11.3.
- **Settings recorded in the no-shader report:** 1920 × 1009 window, 16-chunk render distance, 12-chunk simulation distance, FOV 85 and a 4 GiB Java heap limit.
- **Shader run:** Complementary Unbound r5.9.3, with `enableShaders=true` confirmed in Iris settings.

Each run contains **16 measured phases of 20 seconds**. For each of the four scenes, the order was **OFF → FULL → FULL → OFF**, giving two measurements per mode after warm-up and settling. FPS below is calculated as **total recorded frames ÷ total measured time** across the two repetitions; displayed values are rounded.

**OFF** disables DMO at runtime while the other installed mods remain active. **FULL** enables DMO with the additional display-distance limit set to **0** for these comparisons. The tables therefore show DMO's additional effect in this modpack, without shortening display distance. This is not a comparison against a clean vanilla installation.

### Without shaders

| Scene | DMO OFF, FPS | DMO FULL, FPS | Change |
| --- | ---: | ---: | ---: |
| Displays in front of the camera | 312.3 | 312.3 | ≈0% |
| Camera turned away from displays | 1037.3 | 1228.0 | +18.4% |
| Opaque wall between camera and displays | 309.4 | 567.6 | **+83.5%** |
| Glass between camera and displays | 308.2 | 307.4 | −0.3% |

### With Complementary Unbound r5.9.3

| Scene | DMO OFF, FPS | DMO FULL, FPS | Change |
| --- | ---: | ---: | ---: |
| Displays in front of the camera | 184.5 | 184.2 | −0.2% |
| Camera turned away from displays | 380.8 | 382.9 | +0.6% |
| Opaque wall between camera and displays | 185.1 | 325.2 | **+75.7%** |
| Glass between camera and displays | 181.7 | 181.3 | −0.2% |

### Frame times and slow frames behind the opaque wall

| Renderer | Mean frame time, OFF → FULL | 1% low FPS, OFF → FULL |
| --- | ---: | ---: |
| No shaders | 3.23 → 1.76 ms | 135.8–137.9 → 199.3–200.0 |
| Complementary Unbound r5.9.3 | 5.40 → 3.08 ms | 104.2–106.5 → 168.8–170.9 |

The 1% low values are the **range of the two individual repetitions**, not a pooled percentile. Each phase calculates 1% low FPS from the mean duration of its slowest 1% of frames. Higher values indicate better performance during slow frames. Mean frame time fell by **45.5% without shaders** and **43.1% with shaders** in this scene.

### What changed

The reported mean number of prepared display render states per frame was the same in both renderer configurations:

| Scene | DMO OFF | DMO FULL |
| --- | ---: | ---: |
| Displays in front of the camera | 600 | 600 |
| Camera turned away from displays | 60 | 30 |
| Opaque wall between camera and displays | 600 | 300 |
| Glass between camera and displays | 600 | 600 |

These are **prepared render states**, rather than GPU draw-call counts or a count of all loaded entities.

The largest measured benefit was behind an opaque wall: **309.4 → 567.6 FPS without shaders** and **185.1 → 325.2 FPS with shaders**. That improvement appeared in both repetitions and was accompanied by better 1% low FPS.

Turning away from the displays gave **+18.4% without shaders**, while the shader run gained only **+0.6%**, despite the lower prepared-state count. Preparing fewer states does not by itself guarantee a proportional FPS increase. The front-facing and glass scenes showed little change in average FPS.

These preliminary results cover **one PC, one synthetic arena and two repetitions per mode**. The quick plan enables several DMO optimizations together, so it does not isolate the contribution of each algorithm. Results depend on the scene, hardware, resource packs and shaders; no universal FPS gain is claimed.

# Исторические замеры DMO 0.7.1


В экспериментальной **0.8.0 alpha** появился параметр `cacheBlockDisplayGeometry`: **Mod Menu → Display Model Optimizer → Дополнительно → Кэш геометрии block_display**. Он сохраняет преобразованную геометрию между кадрами, чтобы ускорить подготовку видимых моделей, включая сцену перед камерой и за стеклом. Освещение, оттенки и преобразования сущности рассчитываются обычным способом; кэш ограничен по объёму и сбрасывается при смене ресурсов, мира и настроек. Подробнее — [алгоритм и порядок сравнения](docs/BLOCK_GEOMETRY_CACHE.md). **Замеры FPS ниже относятся к 0.7.1 без этой функции.**

Замеры предоставлены **15 октября 2026 года**: **DMO 0.7.1**, отдельный инструмент DMO Benchmark, план `quick`, одиночный мир с тестовой ареной на **600 item/block display-сущностей**.

### Условия и методика

- **Компьютер:** AMD Ryzen 5 5600, NVIDIA GeForce RTX 3070 8 ГБ, 16 ГБ оперативной памяти.
- **Зафиксированная сборка:** Minecraft 26.3, Fabric Loader 0.19.5, Java 25, Sodium 0.9.2, Iris 1.11.7 и Entity Culling 1.11.3.
- **Параметры из отчёта без шейдеров:** окно 1920 × 1009, дальность прорисовки 16 чанков, симуляции — 12 чанков, FOV 85, максимальный heap Java — 4 ГиБ.
- **Прогон с шейдерами:** Complementary Unbound r5.9.3; включение подтверждено параметром Iris `enableShaders=true`.

Каждый прогон содержит **16 измеряемых этапов по 20 секунд**. Для каждой из четырёх сцен использовался порядок **выключен → включён → включён → выключен**: по два замера каждого режима после разогрева и стабилизации. FPS в таблицах рассчитан как **суммарное количество кадров ÷ суммарное время измерения** двух повторов. Значения округлены.

В режиме **OFF** DMO выключен настройкой, остальные установленные моды продолжают работать. В режиме **FULL** DMO включён, а дополнительный лимит дальности дисплеев в этих сравнениях установлен в **0**. Поэтому таблицы показывают дополнительный эффект DMO в этой сборке без сокращения дальности моделей. Базовый режим также содержит Sodium, Iris и Entity Culling.

### Без шейдеров

| Сцена | DMO выключен, FPS | DMO включён, FPS | Изменение |
| --- | ---: | ---: | ---: |
| Дисплеи перед камерой | 312,3 | 312,3 | ≈0% |
| Камера развёрнута от дисплеев | 1037,3 | 1228,0 | +18,4% |
| Между камерой и дисплеями — непрозрачная стена | 309,4 | 567,6 | **+83,5%** |
| Между камерой и дисплеями — стекло | 308,2 | 307,4 | −0,3% |

### С Complementary Unbound r5.9.3

| Сцена | DMO выключен, FPS | DMO включён, FPS | Изменение |
| --- | ---: | ---: | ---: |
| Дисплеи перед камерой | 184,5 | 184,2 | −0,2% |
| Камера развёрнута от дисплеев | 380,8 | 382,9 | +0,6% |
| Между камерой и дисплеями — непрозрачная стена | 185,1 | 325,2 | **+75,7%** |
| Между камерой и дисплеями — стекло | 181,7 | 181,3 | −0,2% |

### Время кадра и медленные кадры за непрозрачной стеной

| Рендер | Среднее время кадра, выкл. → вкл. | 1% low FPS, выкл. → вкл. |
| --- | ---: | ---: |
| Без шейдеров | 3,23 → 1,76 мс | 135,8–137,9 → 199,3–200,0 |
| Complementary Unbound r5.9.3 | 5,40 → 3,08 мс | 104,2–106,5 → 168,8–170,9 |

Для 1% low указан **диапазон двух отдельных повторов**. Это не объединённый процентиль всего прогона: в каждом этапе 1% low FPS рассчитывается по среднему времени 1% самых медленных кадров. Более высокое значение означает лучшую производительность на медленных кадрах. Среднее время кадра в этой сцене уменьшилось на **45,5% без шейдеров** и **43,1% с шейдерами**.

### Что изменилось

Среднее количество подготовленных состояний рендера дисплеев на кадр совпадало в обоих вариантах рендера:

| Сцена | DMO выключен | DMO включён |
| --- | ---: | ---: |
| Дисплеи перед камерой | 600 | 600 |
| Камера развёрнута от дисплеев | 60 | 30 |
| Между камерой и дисплеями — непрозрачная стена | 600 | 300 |
| Между камерой и дисплеями — стекло | 600 | 600 |

Это **подготовленные состояния рендера**; их количество отличается от числа вызовов отрисовки GPU и общего количества загруженных сущностей.

Самый большой измеренный эффект получен за непрозрачной стеной: **309,4 → 567,6 FPS без шейдеров** и **185,1 → 325,2 FPS с шейдерами**. Прирост наблюдался в обоих повторах и сопровождался улучшением 1% low.

При развороте камеры от дисплеев прирост составил **+18,4% без шейдеров**, а с шейдерами — только **+0,6%**, хотя количество подготовленных состояний также уменьшилось. Снижение этого счётчика само по себе не гарантирует пропорционального роста FPS. Перед камерой и за стеклом средний FPS почти не изменился.

Это предварительные результаты для **одного компьютера, одной синтетической арены и двух повторов каждого режима**. План quick включает несколько оптимизаций DMO совместно и не определяет вклад каждого алгоритма по отдельности. Результат зависит от сцены, оборудования, ресурс-паков и шейдеров; универсальный прирост FPS не заявляется.
